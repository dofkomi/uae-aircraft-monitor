# بوت مراقبة الطائرات — الإمارات 🇦🇪

بوت تليجرام يرصد حركة الطائرات في المجال الجوي للإمارات باستخدام **بيانات ADS-B العامة والمجانية**،
ويرسل **كل ساعة** دراسة تحليلية مكتوبة للبيانات ثم التقرير المفصّل. التقرير يركّز على:

1. **الدولة التي انقطع فوقها الإشارة** لكل طائرة إماراتية (أو الدولة القريبة إن كان آخر
   موقع فوق المياه)، مع ترتيب الدول حسب عدد الحالات.
2. **الطائرات التي هبطت في الخارج ثم واصلت إلى وجهة غير الإمارات**، مع تمييز الطائرات
   الإماراتية أو المستأجرة من قِبل جهات إماراتية.
3. أعداد الطائرات العسكرية/المدنية المرصودة وحالة مصادر البيانات.
4. **إثراء OSINT مجاني**: المسار المجدول للرحلة (adsbdb) وهل ما تزال الطائرة تبث
   عالمياً بعد غيابها عن منطقتنا (adsb.lol).

> مسار «روما ← نجامينا» المذكور في الأمثلة **توضيحي فقط**؛ لا يوجد أي مسار مُبرمج
> في البرنامج. المنطق عام: أي هبوط في الخارج يليه هبوط في دولة أخرى غير الإمارات
> يُسجَّل كحالة «وجهة غير الإمارات».

## المصادر المجانية المستخدمة

| المصدر | المفتاح | الحد المجاني | الغرض |
|--------|---------|--------------|-------|
| [adsb.lol](https://api.adsb.lol/) | لا يحتاج | مجاني بالكامل | المصدر الأساسي — مواقع ونداءات وتعريف الطائرة |
| [adsb.fi](https://opendata.adsb.fi/) | لا يحتاج | مجاني بالكامل | مصدر احتياطي بنفس الصيغة تماماً — يضمن التغطية عندما يردّ adsb.lol بـ429 |
| [OpenSky Network](https://opensky-network.org/api) | اختياري (مجاني) | 400 رصيد/يوم (مجهول) أو 4,000 (مسجّل) | مصدر ثانوي + استعلام الطائرات بالـ ICAO24 عالمياً |
| [Nominatim / OpenStreetMap](https://nominatim.openstreetmap.org/) | لا يحتاج | طلب/ثانية | تحديد اسم الدولة من إحداثيات آخر إشارة |
| [OurAirports](https://ourairports.com/data/) | لا يحتاج | ملف CSV عام | أقرب مطار لنقطة الهبوط/الإقلاع |
| [adsbdb.com](https://www.adsbdb.com/api/) + [hexdb.io](https://hexdb.io/) | لا يحتاج | مجاني | إثراء بيانات التسجيل ونوع الطائرة + **المسار المجدول للرحلة** (`/v0/callsign/`) |
| [adsb.lol](https://api.adsb.lol/) (`/v2/hex/`) | لا يحتاج | مجاني | **البث العالمي**: هل ما تزال الطائرة تُرصد بعد غيابها عن منطقتنا؟ |
| [Google AI Studio](https://aistudio.google.com/) / [Groq](https://console.groq.com/) / [OpenRouter](https://openrouter.ai/) | مفتاح مجاني | طبقة مجانية | **كتابة الدراسة التحليلية** (اختياري — يوجد محرّك محلي بديل) |

> لا يوجد أي مصدر مدفوع أو مفتاح API مدفوع في هذا المشروع. مفاتيح نماذج الذكاء
> الاصطناعي اختيارية ومجانية، وإن غابت يعمل **المحرّك المحلي المكتوب** تلقائياً.

## التثبيت والتشغيل

```bash
cd uae-aircraft-monitor
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env      # Windows: copy .env.example .env
```

عدّل `.env`:

1. احصل على توكن من [@BotFather](https://t.me/BotFather) وضعه في `TELEGRAM_BOT_TOKEN`.
2. أرسل `/start` للبوت، وسيُسجّل محادثتك تلقائياً في `data/chats.json`
   (أو حدد `TELEGRAM_CHAT_IDS` يدوياً).
3. شغّل البوت:

```bash
python main.py
```

### اختبار سريع بدون تليجرام

```bash
python main.py --once
```

سيجلب بيانات واحدة ويطبع التقرير في الطرفية. في المرة الأولى ينزّل ملف المطارات
(حوالي 12 ميغابايت) ويحفظ نسخة مُصفّاة في `data/airports.csv`، ثم يعمل بدون إنترنت.

### تشغيل دائم على خدمة سحابية مجانية

#### الخيار 1 — Oracle Cloud Always Free (موصى به: يعمل 24/7 فعلياً)

Oracle تمنح **VM مجانية مدى الحياة** (Always Free)، وهي الأنسب لأن البوت يحتاج عملية
مستمرة لاستقبال الأوامر وإرسال التقارير كل ساعة.

1. أنشئ حساباً على <https://cloud.oracle.com/free> (يتطلب بطاقة للتحقق فقط، لا خصم).
2. أنشئ VM: Image = **Ubuntu 22.04/24.04**، Shape = `VM.Standard.E2.1.Micro`
   (أو `VM.Standard.A1.Flex` بسعة 1 OCPU / 6GB إن توفر). نزّل مفتاح SSH.
3. من جهازك (PowerShell داخل مجلد المشروع):

   ```powershell
   .\deploy\upload.ps1 -Host "ubuntu@<IP_العام>" -Key "C:\path\to\ssh-key.key"
   ```

4. على الخادم:

   ```bash
   sudo bash /opt/uae-aircraft-monitor/deploy/setup_server.sh
   ```

   السكربت يثبّت المتطلبات، ينزّل بيانات المطارات، ويثبّت الخدمة كـ `systemd`
   مع `Restart=always` (تعمل تلقائياً بعد إعادة تشغيل الخادم).

5. راقب السجلات:

   ```bash
   sudo journalctl -u uae-aircraft-monitor -f
   ```

> ملاحظة: Oracle قد تستعيد الـ VM إذا بقيت خاملة تماماً 7 أيام؛ طلبات البوت الدورية
> كل دقيقتين تجعلها نشطة عملياً.

#### الخيار 2 — GitHub Actions (مجاني 100% بلا بطاقة ائتمان)

مناسب إن لم ترغب ببطاقة أو خادم. يعمل بجدولة كل ساعة عبر `--send-once`.
المستودع المحلي جاهز ومُهيّأ بالفعل (تم `git init` وعمل commit أول).

1. أنشئ مستودعاً فارغاً على GitHub باسم `uae-aircraft-monitor`
   (**اجعله Public** لتكون دقائق Actions غير محدودة).
2. اربطه وادفع من جهازك:

   ```bash
   cd uae-aircraft-monitor
   git remote add origin https://github.com/<USERNAME>/uae-aircraft-monitor.git
   git push -u origin main
   ```

3. في المستودع: `Settings → Secrets and variables → Actions` وأضف **سرّاً واحداً فقط**:
   - `TELEGRAM_BOT_TOKEN` = توكن البوت (إلزامي)
   - اختياري (لتفعيل الدراسة بنموذج ذكاء اصطناعي مجاني): واحد فقط من
     `GEMINI_API_KEY` أو `GROQ_API_KEY` أو `OPENROUTER_API_KEY`.
     بدون أي منها يعمل المحرّك المحلي المكتوب.
   - لتفعيل خطّ التحليل الثلاثي (Groq ← Gemini ← OpenRouter) أضف الثلاثة معاً.

   > **`TELEGRAM_CHAT_IDS` لم يعد مطلوباً:** معرّفات المحادثات المسموح لها
   > بالاستلام محفوظة في `data/chats.json` داخل المستودع (قائمة سماح صريحة،
   > لا يفتح البوت لأحد). إن أضفت السرّ فهو يتقدّم على الملف. يمكن إضافته
   > كـ *Variable* أيضاً (الـ workflow يقرأ `secrets.X || vars.X`).

4. من تبويب **Actions** اختر «UAE Aircraft Report» ثم **Run workflow** لتجربة فورية.
   بعدها يعمل تلقائياً كل ساعة.
5. إن فشل أي تشغيل، يكتب الـ workflow ملف `data/last-failure.md` في المستودع
   يوضّح أي إعداد ناقص مع آخر 150 سطراً من السجل — بلا حاجة لتسجيل الدخول.

#### إن لم تُطلق الجدولة أي تشغيل

`schedule` في GitHub ليس عقداً مضموناً: المستودعات/الحسابات الجديدة قد تبقى
بلا أي تشغيل مجدول ساعات أو أكثر، وGitHub نفسه يؤجّل مواعيد رأس الساعة عند
الضغط. الحلّ المضمون: مُشغِّل خارجي مجاني يستدعي واجهة `workflow_dispatch`
(نفس ما يفعله زر Run workflow) كل ساعة:

```bash
curl -X POST \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/<USERNAME>/uae-aircraft-monitor/actions/workflows/report.yml/dispatches \
  -d '{"ref":"main"}'
```

* أنشئ توكن **fine-grained** مقصوراً على هذا المستودع بصلاحية واحدة:
  `Actions: Read and write` (لا تحتاج أي صلاحية على الكود).
* أضفه في [cron-job.org](https://cron-job.org) (مجاني) كطلب `POST` كل ساعة.
* الحماية من التكرار تبقى فعّالة: `data/last-send.txt` يسمح بتقرير واحد على
  الأكثر لكل ساعة UTC (مع نافذة 10 دقائق ضد إعادة المحاولة)، فلا يُسقط
  اختبارٌ يدوي تشغيل الساعة التالي. `data/last-daily.txt` يمنع تكرار
  التقرير المفصّل قبل 23 ساعة.
* للتجربة اليدوية الفورية (تجاوز حماية الساعة) شغّل *Run workflow* مع
  تفعيل الخيار `force`.

> في هذا الوضع لا يستقبل البوت أوامر `/report` مباشرة (لا يوجد polling متصل)،
> لكن التقارير تصل تلقائياً كل ساعة. ملف `.github/workflows/report.yml`
> يحفظ قاعدة البيانات بين التشغيلات عبر `actions/cache`، ويُبقي الجدولة نشطة
> بتحديث ملف صغير مرة كل ~30 يوماً (GitHub يعطّل الجدولة بعد 60 يوماً خمول).

## الأوامر

| الأمر | الوصف |
|-------|-------|
| `/start` | معلومات البوت (لا يمنح صلاحية؛ البوت خاص) |
| `/report` | تحديث البيانات وإرسال الدراسة التحليلية + التقرير المفصّل (حد أدنى 60 ثانية بين الطلبات) |
| `/analysis` | الدراسة التحليلية المكتوبة وحدها |
| `/status` | حالة البوت وصحة كل مصدر + مزوّد التحليل |
| `/chats` | عرض المحادثات المسجّلة |
| `/addchat <id>` | إضافة محادثة إلى قائمة الاستلام (مالك البوت فقط) |
| `/removechat` | إزالة المحادثة الحالية من القائمة الديناميكية |
| `/stopchat` | إيقاف التقارير لهذه المحادثة |
| `/help` | المساعدة |

## الأمان والخصوصية

- **البوت خاص (fail-closed):** لا يستجيب إلا للمحادثات الموجودة في
  `TELEGRAM_CHAT_IDS` أو التي أضافها المالك بـ `/addchat`. إن كانت القائمة فارغة
  فلن يستجيب لأحد — لا يوجد «سماح للجميع». لذلك `/start` لا يسجّل أي محادثة
  جديدة تلقائياً، وأي محاولة غير مصرّح بها تُرفض وتُسجَّل في السجلات.
- **حماية الحصة:** `/report` محدود بمرة كل 60 ثانية لكل محادثة لمنع استنزاف رصيد
  OpenSky المجاني أو إغراق تليجرام. طلبات OSINT محدودة لكل دورة جلب
  (`OSINT_MAX_ROUTES_PER_POLL`) وتُخزَّن نتائجها مؤقتاً في SQLite.
- **مفاتيح الذكاء الاصطناعي:** تُقرأ من `.env` فقط، ولا تُسجَّل ولا تُرسل في التقرير.
  لا يوجد أي مفتاح داخل الكود أو في المستودع.
- **التوكن لا يظهر في السجلات:** مكتبة `httpx` تطبع عنوان كل طلب (وفيه التوكن)،
  لذلك يخفض `secure_logging.py` مستوى تسجيلها إلى WARNING ويحجب أي نمط يشبه
  توكن تليجرام قبل كتابته. لا تشارك مخرجات التشغيل مع أحد.
- **لا أسرار في Git:** `.env` و`data/*.db` مستثناة في `.gitignore`،
  و`.env.example` يحتوي قيماً وهمية فقط.
  الاستثناء الوحيد المتعمَّد: `data/chats.json` مُتتبَّع لأنه **قائمة سماح**
  (معرّفات محادثات) لا سرّ — وبفضله يعمل التشغيل السحابي بلا إعداد إضافي.
  معرّف المحادثة وحده لا يسمح لأحد بإرسال رسائل إلى البوت أو قراءتها.
- **GitHub Actions:** الأسرار تُضاف عبر *Settings → Secrets* فقط، ولا تُكتب في
  ملف الـ workflow. أضفنا `concurrency` لمنع تشغيل نسختين متزامنتين (تقارير
  مكرّرة وتعارض على ذاكرة التخزين المؤقت).
- **إن تسرّب التوكن** (ظهر في لقطة شاشة أو سجل أو مستودع): أبطله فوراً من
  `@BotFather → /revoke` وأنشئ غيره، ثم حدّث `.env` وسرّ GitHub.
- **حدود قانونية:** البيانات من شبكات ADS-B تطوعية عامة، والبوت للرصد البحثي
  فقط. لا تستخدمه لتعقّب أفراد أو لأي غرض يخالف قوانين بلدك أو شروط المصادر.

## كيف يعمل رصد فقدان الإشارة وتحديد الدولة؟

- كل دقيقتين (قابل للضبط) يجلب البوت حالة الطائرات من المصادر ويدمجها.
- **كل موقع في التقرير يُعرَض مع الدولة**، لا الإحداثيات وحدها: اسم الدولة وعلمها
  يظهران بجانب كل طائرة (مثال: `🌍 🇦🇪 الإمارات · 📍 24.4114°N 54.4820°E`)، مع
  قسم «توزيع الطائرات الحالية حسب الدولة» في أعلى التقرير.
- تحديد الدولة يجري **محلياً** من حدود Natural Earth المحفوظة في
  `data/countries.geojson` (اختبار نقطة داخل مضلّع + مرشّح صندوق إحداثيات):
  سريع، بلا شبكة، وبلا استهلاك حصة Nominatim. النقاط فوق المياه تظهر صراحةً
  «🌊 فوق المياه / خارج حدود الدول» بدل تخمين دولة أقرب مطار.
- إذا اختفت طائرة كانت تظهر لمدة تتجاوز `SIGNAL_LOSS_MINUTES` (20 دقيقة افتراضياً)،
  يُسجَّل حدث فقدان إشارة.
- يُستعرف من إحداثيات **آخر موقع مُستقبَل** اسم الدولة (محلياً أولاً، ثم Nominatim
  عند الحاجة)، ويُحفظ في قاعدة البيانات، ويظهر في التقرير مع عدد الحالات لكل دولة.
- **الطائرات الإماراتية فقط:** إن كان آخر موقع فوق المياه (شائع قرب الساحل) تُذكر
  **أقرب دولة** ضمن `NEAREST_COUNTRY_MAX_KM` (200 كم افتراضياً) بوسم «(قريبة)»،
  بدل ترك الموقع بلا دولة. أحداث الطائرات غير الإماراتية لا تُنسب لدولة قريبة.
- إذا تعذّر كل ما سبق ولم تتوفر حدود الدول، يُستخدم أقرب مطار من OurAirports كبديل.
- يميّز البوت بين «غياب بث داخل المنطقة» و«على الأرجح خرجت من نطاق الاستقبال».

## كيف يعمل تتبّع الهبوط والوجهات؟

- عند هبوط طائرة (على الأرض أو ارتفاع ≤ 1200 قدم وسرعة ≤ 80 عقدة) يُحدَّد أقرب
  مطار خلال `LANDING_MAX_KM`، ويُسجَّل المطار والدولة ووقت الهبوط.
- عند هبوطها التالي يُقارن بمطار الهبوط السابق؛ إذا كانا في دولتين **خارج الإمارات**
  تُسجَّل حالة «وجهة غير الإمارات».
- الطائرات المرتبطة بالإمارات (تسجيل `A6-`، نداءات UAE/ETD/FDB/ABY، أو معرّفات
  تُحدّدها في `UAE_WATCH_ICAO24`) تظهر في قسم مميز بالتقرير.
- لمتابعة هذه الطائرات **خارج** منطقة الإمارات، يستعلم البوت عن معرّفاتها عبر
  OpenSky كل `WATCHLIST_INTERVAL_SECONDS` (استعلام واحد بـ 1 رصيد مهما بلغ عددها).
  القائمة تُضاف إليها تلقائياً الطائرات الإماراتية المرصودة محلياً عند تفعيل
  `WATCHLIST_DYNAMIC`، وتُحفظ في قاعدة البيانات فتبقى بعد إعادة التشغيل.
- **ميزانية OpenSky:** 400 رصيد/يوم للمجهول، وكل استعلام يكلّف رصيداً. لذلك
  صندوق الإمارات كل `OPENSKY_INTERVAL_SECONDS` (30 دقيقة = 48/يوم) والقائمة كل
  15 دقيقة (96/يوم) = 144/يوم. عند بلوغ `OPENSKY_DAILY_CREDITS` أو استلام 429
  يتوقف المصدر مؤقتاً بدل استنزاف الحصة. adsb.lol يبقى المصدر الأساسي كل دقيقتين
  بلا مفتاح ولا حصة، ويليه **adsb.fi** بنفس الصيغة تلقائياً عند ردّ 429 (تبريد
  15 دقيقة لكل مصدر على حدة بدل تقرير فارغ).

## كيف تعمل الدراسة التحليلية المكتوبة (ذكاء اصطناعي مجاني)؟

كل تقرير يبدأ بـ **دراسة تحليلية مكتوبة** بالعربية (وليست بيانات وصفية فقط):
الخلاصة، الطائرات الإماراتية، انقطاع الإشارة، الهبوطات والوجهات، وما يستحق المتابعة.

- **نماذج مجانية متعددة** بلا بطاقة دفع: `GEMINI_API_KEY` (Google AI Studio) أو
  `GROQ_API_KEY` (Groq) أو `OPENROUTER_API_KEY` (OpenRouter). يُكتشف المزوّد
  تلقائياً بحسب المفتاح الموجود، ويمكن فرضه بـ `AI_PROVIDER`.
- **اكتشاف اسم النموذج تلقائياً** من قائمة النماذج المتاحة لدى المزوّد، حتى لا
  يتعطّل البوت عند تغيّر أسماء النماذج. وإن رفض المزوّد النموذج (404/503) أو أعاد
  رداً فارغاً، ينتقل البوت تلقائياً إلى النموذج التالي في القائمة. يمكن فرض نموذج
  بـ `AI_MODEL`.
- **بلا مفتاح؟** يعمل **محرّك محلي مكتوب بالقواعد** (`build_local_analysis`) ينتج
  نفس الأقسام من البيانات نفسها، فلا يبقى التقرير أرقاماً فقط.
- النموذج يتلقى **لقطة JSON مضغوطة** بلا HTML وبلا إحداثيات خام، مع تعليمات صارمة:
  لا يخترع بيانات، ويفصل الحقيقة المرصودة عن الاستنتاج، ولا يجزم بسبب اختفاء الإشارة.
- `AI_REPORT_MODE`: `both` (افتراضي: دراسة + تفاصيل) | `analysis` (الدراسة وحدها) |
  `off` (التفاصيل فقط).

## كيف يعمل إثراء OSINT المجاني؟

- **المسار المجدول (adsbdb):** يُحوَّل نداء الاستدعاء إلى خط طيران ومطارَي الإقلاع
  والوصول (مثال: `UAE1` ← دبي DXB → لندن LHR · Emirates)، ويظهر بجانب الطائرة
  والهبوط والحدث.
- **مقارنة الوجهة:** إذا هبطت طائرة في مطار يختلف عن وجهتها المجدولة يظهر تنبيه
  «مغادرة عن المسار المجدول» (المسار المجدول قد يكون قديماً، والوجهة الفعلية تُعرف
  من الهبوط المرصود).
- **البث العالمي (adsb.lol):** عند انقطاع إشارة طائرة إماراتية يسأل البوت: هل ما
  تزال تُرصد في مكان آخر؟ إن كانت تبث فالإشارة **لم تتوقف**، بل خرجت من نطاق
  مستقبلاتنا — وهذا يمنع الاستنتاج الخاطئ بأن جهاز التعريف أُغلق.
- كل النتائج تُخزَّن في جدول `osint_cache` لتفادي تكرار الطلبات واحترام حدود الخدمات
  المجانية.

## الدراسة التحليلية: منهجية لا سرد

النموذج لا يُطلب منه وصف البيانات بل **تحليلها**، وفق أقسام ثابتة:

1. نطاق الرصد وجودة البيانات — هل المصادر تعمل؟ هل هناك ثغرة تغطية؟
2. الحركة الجوية — الارتفاع والسرعة وأكواد الطوارئ.
3. الطائرات الإماراتية — أين هي الآن.
4. انقطاع الإشارة — وهل الطائرة ما تزال تبث عالمياً (تغطية) أم لا (توقف فعلي).
5. الهبوطات والوجهات — مقارنة الهبوط بالمسار المجدول من OSINT.
6. تقدير الطابع العسكري — مؤشرات مركّبة بدرجة احتمالية.
7. وجهات غير مبرمجة — مطار جديد أو مخالفة للمسار.
8. الاستنتاجات — ما تأكد، وما استُبعد، وما بقي غير مفسّر.

قواعد صارمة في التعليمات: **لا تكرار** (كل رقم يُذكر مرة واحدة)، ولا أسماء
حقول إنجليزية، وكل استنتاج مسند إلى رقم. وعند فشل النموذج يعمل المحرّك
المحلي بنفس الأقسام.

## نسختان قابلة للاستغلال: PDF و DOCX

مع كل تقرير ساعة يرسل البوت **ملفَّين** بعد الرسالة التحليلية:

- `uae-aircraft-report-YYYYMMDD-HHMM.pdf` — تنسيق RTL بخط Amiri مضمّن، جاهز
  للطباعة والأرشفة، مع فهرس محتويات وأرقام صفحات.
- `uae-aircraft-report-YYYYMMDD-HHMM.docx` — قابل للتعديل والاستخراج في Word
  وLibreOffice وGoogle Docs.

يُولَّد الملفان محلياً بلا إنترنت من نفس النصوص عبر `report_docs.py`

## تنبؤ الطابع العسكري

بدل الاكتفاء بتصنيف «نوع الطائرة»، يجمع البوت مؤشرات مركّبة ويحسب درجة احتمالية
(0–100%) لكل طائرة غير مصنّفة:

| المؤشر | الأثر |
|--------|-------|
| نوع عسكري معروف (F16، C130، AH64…) | +85 |
| نوع مدني شائع (B738، A320…) | −70 |
| اسم مشغّل/نموذج عسكري | +55 |
| نداء عسكري (RASHD، ARMY…) | +50 |
| نداء خطوط مدنية | −55 |
| تسجيل عسكري / تسجيل A6- | +50 / −55 |
| لا تبث نداءً إطلاقاً | +20 |
| squawk في نطاق عسكري | +25 |
| طيران منخفض جداً بسرعة عالية | +20 |

تظهر النتيجة في التقرير بعبارة (عسكرية مرجّحة/غير حاسمة/مدنية مرجّحة) مع الأسباب،
ويُرسل نفس المرشّحين إلى نموذج الذكاء الاصطناعي ليصدر تقديره النهائي في قسم
«تقدير الطابع العسكري». **هذا تقدير لا تأكيد**، وكثير من العسكري لا يبث ADS-B.

## رصد الوجهات والرحلات غير المبرمجة

- **مطار جديد:** أول هبوط مرصود لطائرة لها تاريخ سابق في مطار لم تُرصد فيه من قبل.
- **مخالفة المسار:** الهبوط الفعلي يختلف عن وجهة المسار المجدول (adsbdb).
- يظهر كلاهما في قسم «وجهات غير مبرمجة سابقاً» وفي عدّاد الملخص، ويُخزَّن
  العمودان `new_airport` و`unplanned` في جدول `landings`.

### ⚠️ حدود مهمة يجب معرفتها

- بيانات ADS-B **بثّ عام وغير مشفّر**؛ أي مستقبل هواة يمكنه التقاطه. البوت لا يخترق
  أي نظام ولا يصل إلى بيانات غير عامة.
- **«الدولة التي انقطع فيها الإشارة» هي دولة آخر موقع مُستقبَل**، وليست بالضرورة
  الدولة التي أُغلق فيها الجهاز قصداً. قد يكون الغياب خروجاً من نطاق المستقبلات
  التطوعية أو فجوة في الاستقبال أو هبوطاً.
- **الوجهة اللاحقة مُستنتَجة من مكان الهبوط التالي**، وليست من خطة طيران رسمية؛
  قد لا يُرصد الهبوط الوسيط إذا كانت الطائرة خارج تغطية الشبكة.
- **كثير من الطائرات العسكرية لا تبث ADS-B أصلاً** أثناء مهامها، لذا قد لا تظهر
  في التقارير.
- التصنيف «عسكري/مدني» و«مرتبط بالإمارات» تقديري ويعتمد على بيانات عامة، وقابل
  للضبط في `classifier.py`.
